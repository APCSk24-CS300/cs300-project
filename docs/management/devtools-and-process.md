## Process

Our team follows Scrum throughout the project. Each project assignment (PA) is one sprint lasting approximately 2–3 weeks.

### Sprint meetings

- **Sprint Planning (once per sprint):** Plan the work and assign tasks before work begins.
- **Scrum meetings (twice per sprint):** Meet at separate points during the sprint to report progress, upcoming work, and obstacles.
- **Sprint Review (once per sprint):** Review the completed work at the end of the sprint.

We document meetings using the format in [Weekly Reports](weekly-reports.md) (also specified in PA1), including attendance, each member's status, obstacles, and follow-up actions.

### Task tracking

We use Jira to track all project work, including coding, documentation, and self-training tasks. We follow a few rules to ensure transparency and efficiency:

- Create and assign each task **before** starting the work. Assign exactly one owner to each task.
- Tasks' creation date, assignment date, and actual completion date are recorded. Creation and assignment may happen on the same day.
- When the owner begins work on a task, it must be moved to the "In Progress" column; when work is finished, the task must be moved to "Needs Review" column. After the task has been reviewed, the Scrum master moves it to the "Done" column.
- Mark a task complete only when the work is finished; do not create, assign, and close it afterward in one step.

We provide an ad-hoc definition for Task and Story task types:
- Task type involves directly modifying the codebase; the task ends as a pull request.
- Story type involves doing miscellaneous work such as communication or administrative work; it does not affect the codebase and does not have a pull request.

## Development tools

- **Moodle:** Receive and submit assignments, as well as course announcements and updates.
- **Class Facebook group or equivalent:** Follow announcements, discussions, and questions.
- **Discord and Messenger:** Communicate with teammates. We also configure our Discord server with Github and Jira webhooks so members can keep track of development better.
- **Jira:** Plan sprints, assign owners, and track task progress.
- **GitHub:** Version-control source code and Markdown documentation in a private repository. 
- **Spec Kit:** Manage the specification-to-implementation workflow; setup and initialization will begin in PA2.
- **AI coding tools:** Each member registers for an AI coding assisstant account to support implementation and self-learning.
